# `file://` 콘솔 시점 대조 (A/B) — 절차

**배포 대상 아님.** 설계 §10-2 9-1 · §15-23 의 판정을 다시 하려면 이 절차를 쓴다.

## 왜 대조인가

`file://` 로 열었을 때 나오는 콘솔 에러는 **브라우저와 확장 상태에 좌우된다.** 같은 코드가
깨끗한 Chromium 에서는 0건, 사람 브라우저에서는 1건이 나온다(실측 2026-08-07). 그래서
**"에러 0건"을 절대 판정으로 쓰지 않고, 같은 브라우저에서 작업 전후를 대조한다.** 환경을
상수로 묶으면 원인이 무엇이든 소거된다 — 원인 규명은 필요 없다.

**대조는 반드시 현상이 존재하는 브라우저에서 한다.** 자동화가 재현하지 못한다는 것은
"문제 없음"의 근거가 되지 못한다 (§15-20 과 같은 축).

## 절차

```sh
cd Faraday
git archive main | tar -x -C "<임시경로>/main-copy"     # 비교 시점의 사본을 뽑는다
```

`<임시경로>/main-copy/index.html` 과 작업본 `Faraday/index.html` 을 **같은 브라우저에서**
더블클릭해 열고, 각 창의 콘솔을 비교한다.

| 볼 것 | 통과 조건 |
|---|---|
| 에러 목록 | 두 시점이 **같을 것**. 작업본에만 있는 항목이 있으면 그것이 이번 변경의 회귀다 |
| `[검증]` 로그 | 두 시점이 같을 것 |
| 에러 문구의 경로 | 각 사본의 제 경로를 가리킬 것 — 창을 헷갈리지 않았다는 확인 |

`git archive` 는 커밋 트리만 뽑으므로 미추적 파일이 섞이지 않는다. **사본은 대조가 끝나면
지운다** — 저장소에 남기지 않는다.

## 서버 쪽은 따로다

`http://localhost` 판정은 이 절차가 아니라 §10-2 의 게이트로 한다. 비교 페이지는 `file://`
에서 동작하지 않고(§15-11) 논문 그림 캡처도 전부 로컬 서버 전제이므로, `file://` 대조는
**단독 로드가 깨지지 않았는지**만 본다.
